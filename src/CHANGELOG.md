## 现役档案（2026-08-09 定稿）

**P50 中位 200ns（读数 170-230）/ P90 ~292 / 收入中位 ~1515 / 659 指令/调用 / .text 4.7KB**
对 Tiuntled-1 先手 85-96%（三天前被对方压 87%）。构建命令见 INFRA.md §5。

架构一句话：双单位全管线，5×5 就地扫描（金全窗+弹±1行）→ pext 环距最近金/锚点 →
LUT 三步导向（折返预折叠）+ 位图通行验证 → 受阻单步自愈；烘焙墙（map1 常量）、
开局 BFS 行军 4 轮出角；无视野购买、无敌情、无矿堆记忆（下一战役的加法空间）。

**map1 特化警告**：`BAKED_W1`（墙表）与 `ORT_*`（开局路线）是 map1 常量，换图必须重烘焙（player.cpp 内注有生成方法）。

## 负结果军规（每条都付过学费，勿复活）

1. **冻结红利**：死锁/站桩单位少跑内存会"假快"——延迟读数必配行为体检
2. **墙口袋死锁**：无逃逸回落会永久 STAY——escapeStep 是保命装备
3. 掩码化改写必须带行为回归——纯周期验收放行过语义灾难（ctz 案）
4. unroll 展开 = 位点/text 翻倍 = 平台负优化（四案，含二连体 -64 指令输给 +2KB text）
5. 门控分支的价值是省功：高频用掩码，低频用恒预测门控（开局行军掩码版 +73 判负）
6. 位点 > 指令数；本地热 BTB 看不见位点税，平台批量是唯一裁判
7. 跨环金额加权判负（富度差在驻留深度与信息层，不在目标选择层）
8. 环内金额裁决+驻留深度判负（8.8）：慢方吃的是对手+NPC 双重扫荡后的第三道，
   环内微操是残羹摆盘——真差距在信息与时序
9. 计划块廉价化判负（acts 逆推折返 717 vs 基线 1563）
10. 被动微扫判负：目标与主动单位同区+单槽堆共享 → 双单位收敛互堵死锁
11. LUT 打包/位图合并/O2/falign/PGO：全部无效或负
12. **军备下岗池**：防御性代码（钳位/队友检查类）在可证冗余前提下皆可退役换指令，
    但必须 pair_diff + 行为体检双保险；try/catch 永不下岗
13. 单局 A/B 无判别力（窗噪 ±30ns/收入 ±300）——验收协议见 INFRA §4

## 策略轨遗产（v42 的解剖成果，下一战役的原料）

1. **赢家全是矿堆农**：头部收入 64-78% 来自单轮 ≥6 金的暴击轮；矿堆无争议，
   先手权只裁决新刷金归属
2. **速度即收入引擎**：全图先吃 65% → 残堆沿路自产 → 链式回收
3. 头部形态：旱情 P90=3-4 轮 / 收入曲线全程平 / 双单位均衡
4. 对撞判决：与同速对手的差距 = 每口吃多少（大堆驻留深度）
5. 深耕范本（酱味大鸡 151554）：430ns，96% 后手，靠"半径 ≤3 蹲 12-54 轮吃干堆群"
   赢我们 717 分——**先手权不自动变现，每口含金量是现阶段唯一残余差距**
6. v42 判决史：轮换收入病 → 双扫翻倍；外环巡游判负；矿堆缓存把单位自然拽回有货处；
   视野触发器两版全哑（矿堆喂太忙）
7. 相位教训：一切"避让/竞速/让渡"特性移植前先问行动顺序相位（我方在 NPC 前还是后）
