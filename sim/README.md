# GoldRush 2.0 本地高保真模拟器

> 目标：把平台配额留给最终确认，用本地**同种子配对 A/B**筛选策略改动。
>
> 本模拟器把两类误差分开：机械规则由官方全信息日志逐轮精确回放验证；私有的生成分布与 NPC 策略只能拟合，绝不冒充官方真值。

## 1. 三分钟上手

### 1.1 跑一局

```bash
python3 sim/cli.py \
  --p1 /path/to/a.so \
  --p2 /path/to/b.so \
  --map map1 \
  --seed 42 \
  --games 1 \
  --dispatch fixed \
  --fixed-costs 200,201 \
  --output-dir /tmp/gr-single \
  --jobs 1
```

macOS arm64 不能加载比赛用 Linux x86-64 `.so`；可先用内置 `stay` / `scripted` 做功能测试，正式 `.so` 请在开发机运行：

```bash
python3 sim/cli.py --p1 stay --p2 scripted --map map1 \
  --seed 42 --games 1 --output-dir /tmp/gr-smoke
```

### 1.2 推荐：同种子、换座配对 A/B

```bash
python3 sim/cli.py \
  --p1 /path/to/baseline.so \
  --p2 /path/to/candidate.so \
  --map map1 \
  --seed 1000 \
  --games 20 \
  --paired \
  --dispatch fixed \
  --fixed-costs 200,201 \
  --output-dir /tmp/gr-paired \
  --jobs 8
```

每个 seed 跑两腿：A/P1 对 B/P2、B/P1 对 A/P2。两腿共享同一场景摘要 `scenario_digest`，金币/炸弹意图和 NPC 随机种子均不受策略 RNG 消耗影响。比较 `summary.json` 中两版本跨座位的净收入差，不比较单局绝对收入。

### 1.3 验证

完整验证依赖本地忽略目录中的官方日志：

```bash
python3 sim/validate.py --repo . --output /tmp/gr-validation.json
python3 sim/calibrate_generation.py \
  logs/gr_data/full/g0.txt logs/gr_data/full/g1.txt logs/gr_data/full/g2.txt \
  --output /tmp/generation.json
python3 sim/calibrate_views.py --repo . --maps sim/maps.json \
  --output /tmp/visibility_snapshot.json
```

`validate.py` 只有确定性机械/格式验收失败才返回非零；私有模型偏差进入 `fitted_warning`，不会伪装成机械失败。

## 2. CLI 契约

| 参数 | 含义 |
|---|---|
| `--p1`, `--p2` | 两个 `.so` 路径，或内置 `stay` / `scripted` |
| `--map` | `map1` / `map2` / `map3`、`maps.json`、日志第二行 JSON，或任意完整官方日志 |
| `--seed` | 整数或字符串基种子；相同输入与非 measured 模式产生逐字节相同日志 |
| `--games` | 单局数；`--paired` 时表示配对样本数，每个样本两腿 |
| `--dispatch` | `fixed`（默认）、`p1`、`p2`、`measured` |
| `--fixed-costs` | `fixed` 模式下 P1/P2 的确定性纳秒值；相同耗时 P1 先 |
| `--output-dir` | 官方兼容 `.log` 与确定性 `summary.json` 的输出目录 |
| `--jobs` | `ProcessPoolExecutor` 并发数；每项任务使用新进程，重置 `.so` 全局状态 |

`measured` 用 `perf_counter_ns` 测量真实 ctypes 调用耗时，会影响先手且天然不可逐字节复现。需要可复现实验时不要使用它。

日志保持官方三段格式：第一行选手名、第二行 17×17 地图、随后 500 行回合 JSON。已用**未修改**的 `tools/gamelog.py` 实测解析通过。

| `scenario.py` | 私有 RNG 预物化的金币/炸弹拟合场景与稳定摘要 |

| `cli.py` | 多进程跑批入口 |

| `validate.py` | 一键权威验收 |

| `reports/*.json` | 可审计证据、直方图、残差和逐项验收数字 |

状态含义：**日志证实**＝有官方说明或全信息日志零误差回放；**拟合近似**＝私有分布的经验模型；**未知**＝现有日志不能辨识。

| 能力/规则 | 状态 | 证据与样本量 |
|---|---|---|
| 回合时序：生成→双决策→快方→NPC→慢方 | 日志证实 | FAQ；`dispatch_order` 1500/1500 |
| 两角色按 `k` 切分、`order` 整角色串行 | 日志证实 | 6000/6000 单位轨迹精确 |
| 越界/墙/玩家碰撞跳过，后续步继续 | 日志证实 | 18000 玩家有效动作；定向微用例 |
| 四玩家角色不可重叠；腾空格可进入 | 日志证实 | 3000/3000 phase 四位置互异；微用例 |
| 移入拾取 `ceil(65%)`、余币可重复吃、原地不吃 | 日志证实 | 7751 次正金币进入；16500/16500 actor-round pickup |
| 炸弹扣玩家持金 `ceil(10%)` 后消失 | 日志证实 | 玩家触弹 288 次，损失 5706 |
| NPC 可重叠并会触发/消耗炸弹 | 日志证实 | NPC 触弹 **109 次** |
| 踩踏：成功移入 3+ NPC 格、拾金后扣 `ceil(5%)` | 日志证实 | FAQ；2 个实测事件、微用例 |
| `end.burned` | 日志证实 | **包含炸弹损失与踩踏损失**；1500/1500 物料方程精确 |
| VP 下一轮生效一轮，可连续买，终局扣费 | 日志证实 | 3000 player-round；ABI/微用例 |
| 视野为两己方单位切比雪夫窗并集，边缘裁剪 | 日志证实 | 官方 g3-g10：8000/8000 phase grids；半径 2/3/4 |
| 可见敌人匿名紧凑、NPC 尾槽清空 | 日志证实/ABI | 专项数组和 padding 回归 |
| 风车五区与当前占据 | 日志证实 | 289 格无遗漏；297 快照×5 区 |
| 快照六字段及边界 | 日志证实 | 297×5×6＝**8910/8910** 精确 |
| 完整回合机械结果 | 日志证实 | 3×500；433500/433500 end-grid cells；所有 gold/pickup/burned/trample 精确 |
| 中央金币数量/金额 | 拟合近似 | 1497 常规轮、2611 个格；数量 Poisson λ≈1.744，金额近似离散均匀 1..10 |
| 外圈周期/数量/金额/位置 | 拟合近似 | 121 次事件；间隔 8..16，7..13 格；token `2` 热点权重拟合 |
| 炸弹波 | 拟合近似（时点证实） | 75 波全部在 r=0,20,…,480；16558 eligible exposures / 1307 生成，p≈0.0789 |
| NPC 精确动作 | 未知、拟合近似 | 官方策略不公开；逐动作 12192/31500＝38.70%，三步整串 1488/10500＝14.17% |
| NPC 贪心并列集合上界 | 拟合诊断 | 真动作落入模型最优并列集 17744/31500＝56.33%；说明平局随机不能解释全部误差 |
| map1/map2 | 完整支持 | map1 40 墙/20 热点；map2 24 墙/20 热点 |

### 快照边界（容易错一轮）

在 r=5,10,…,495 发布，标签是 `[r-5,r-1]`：

- `enter` / `leave` / `gold_collected` 聚合行动轮 r-5..r-1；
- `gold_remaining` / `occupants` 采样 **start[r]**，即本轮生成后、任何移动前；
- `gold_generated` 对应相邻 start 采样间的生成 r-4..r，首次 r=5 因从空地 bootstrap 而含 r=0..5。

这套看似错位的语义逐区 1485/1485 精确；按标签直觉统计生成量仅 17/297 个快照全对。

## 5. 生成模型标定

### 5.1 金币

- 全局 3 局/1500 轮，快照生成与剩余约束均零残差，1500/1500 地面物料守恒。
- 中央常规轮拟合：每轮格数 Poisson λ≈1.744，金额近似 `Uniform{1..10}`。首轮 50 格初始化的潜在拆分无法辨识，模型不声称复刻官方 RNG。
- 外圈共确认 121 次生成事件，间隔 8..16 轮；每次 7..13 个不同格。事件形状和值从经验直方图采样。
- 模拟器 8 seed 的热点落点占比 0.5531，真值 0.5412，差 1.2 个百分点。

### 5.2 日志行 2 的 token `2`：不是炸弹候选位

仓库旧说明把 `2` 写成“炸弹刷新位”，全信息日志直接推翻了它。炸弹会出现在全部非墙可用格，token-2 格也会被炸。

`2` 的实测语义是**外圈金币高频热点**：

- 3 局外圈落点 1142 个，其中 618 个在 20 个 token-2 格，占 54.12%；
- 20/20 热点每局都被使用；与中央 9×9 零重叠；
- 原始单格生成率约为普通外圈格 9.67 倍；当前无放回采样器用专属拟合权重 11.336。

需要修正但本任务按边界未修改的旧位置：`tools/gamelog.py` 顶部格式注释、`AGENT.md §3` 对日志第二行的描述。

### 5.3 炸弹

- r=0,20,…,480 共 75/75 波；非波相邻 start/end 炸弹集合无刷新变化；
- 每波在全部 249 个 map1 非墙格中，先排除金币、玩家、NPC，再按 Bernoulli p≈0.0789 采样；
- token-2 热点仍可生成炸弹。其原始炸弹率偏低是金币长期占位降低 eligibility，不是特殊排除规则。

## 6. 对策略有用的实测情报：外圈热点坐标

坐标为 0-based `(row,col)`。map1 的“热点”语义由 3 份全信息日志证实；map2 坐标来自相同 line-2 token，语义按同一地图格式推断，尚无 map2 全信息日志交叉验证。

**map1（20 格）**

```text
(0,4) (0,5) (0,12) (1,6) (1,10)
(5,0) (5,16) (7,1) (7,15) (9,2) (9,14)
(11,0) (11,16) (12,3) (12,13)
(15,6) (15,10) (16,4) (16,5) (16,12)
```

**map2（20 格）**

```text
(0,4) (0,8) (1,6) (1,12) (3,10)
(5,0) (5,16) (7,2) (7,14) (9,1) (9,15)
(11,3) (11,13) (12,0) (12,16)
(13,10) (15,6) (15,12) (16,4) (16,8)
```

这解释了“外圈总池大但全职巡逻仍可能判负”：产出不是均匀铺满外圈，而是高度集中在少量格。正赛新图可直接把任意日志传给 `--map`，token `2` 会自动进入热点权重层。

## 7. NPC：最弱的一环

NPC 官方策略不公开，现有 3 局不足以精确辨识。当前模型每步最大化 `gold / BFS_distance^4`，按最短路移动并每步重规划；每轮 NPC 顺序由独立确定性种子生成，且**每个 NPC 在其真实 dispatch 时点**读取快方和前序 NPC 已更新的地面。

真值诊断：

- 全局 NPC 吃金：g0=5216、g1=7051、g2=6916；旧的 800-1300 是视角日志漏报造成的系统性低估；
- 真值 start occupancy（区域 1..5，10500 暴露）：`[5674,1279,1123,1238,1186]`；
- 真值每轮 NPC pickup：均值 12.79、中位 10、P90 27；
- 真实动作落在当前贪心最优并列集仅 56.33%，清楚表明还有避弹、持金、身份或其他隐藏状态；其中 347/361 个“所有贪心首步均踩弹”的机会选择了非炸弹动作，避弹是明确漏项。

当前未标定模型在 3 个合成弱 bot 场景中仍有明显定向偏差：NPC 总吃金 8631-9272、区域 1 暴露 +927、干净金块 episode P90 8（真值 13）。这会高估中央竞争、低估中央驻留，并相对高估外圈路线。完整数字见 `reports/validation.json`。

**护栏：NPC 模型是本模拟器最弱的一环（逐动作 38.7%）。因此绝对收入数值不可信，同种子配对的相对差值可信。任何用本模拟器得出的结论，都必须以配对 A/B 形式表述，不得引用绝对收入去和平台读数比较。**

## 8. 已知偏差与未知项

1. NPC 的精确 policy、隐藏持币、身份差异和随机源未知；这是最大的、且对中央/外圈比较有方向性的误差。
2. 生成分布来自 map1 的 3 局拟合；正式赛参数可变，模型不是官方 RNG 克隆。
3. map3 只有墙，缺 token-2 外圈热点元数据；中央与炸弹可跑，外圈空间分布会失真。
4. 首轮中央 50 格初始化不能从常规生成过程唯一拆分。
5. `overlap_events` 在 g0-g2 全为空，元素语义未知；合法玩家/NPC 重叠不依赖此字段。
6. 可见敌人顺序官方不保证；模拟器给出确定性紧凑顺序，但策略不能依赖身份/顺序。
7. macOS arm64 不能执行 Linux x86-64 `.so`；机械与 Python policy 验收可本地跑，`.so` 自博弈需开发机。

## 9. 验收数字（当前主体版本）

- 机械回放：1500/1500 轮；433500/433500 end-grid cells；6000 玩家单位与 10500 NPC 轨迹/金币/pickup/actions 全精确；1500/1500 burned、trample、地面和持币物料方程。
- 快照：297 个，5 区×6 字段＝8910/8910。
- 迷雾：官方 g3-g10 共 4000 轮/8000 phase grids 零误差；当前本地 205 份日志共 102500 轮/205000 phase grids 零误差。
- 地图：map1/map2 完整；map3 受限但 500 轮可跑；任意官方日志第二行可加载。
- ABI：`GameInput=1444B`，`GameOutput=36B`，全部字段 offset 对齐。
- 确定性：同 seed 日志逐字节一致；异 seed 分叉；配对两腿摘要相同且座位交换正确。
- 格式：未修改 `tools/gamelog.py` 子进程解析 500 轮成功。
- 性能：macOS arm64 内置 policy 单进程一局约 4.09s；支持多进程跑批。
- Linux x86-64 开发机现役 `.so` 自博弈冒烟：500 轮无非法输出/崩溃；本地拟合场景收入 P1=1414、P2=1007，NPC=6479；3.92s。该绝对收入仅作量级体检，不作平台预测。

## 10. 给优化 Agent 的实验纪律

1. **只看 paired delta**：同一 seed 两腿换座，先对每个 seed 合并，再汇总中位数/均值和胜负号。
2. **不要用 measured 做收益 A/B**：默认 `fixed` 才能逐字节复现。先分别强制 P1/P2 看算法收益，再用 `measured` 单独研究先手阈值。
3. **探索至少 3 对，里程碑 6+6**：沿用 `INFRA.md §4`。平台单局收入噪声约 ±300；本地同 seed 消除了生成噪声，但 NPC 模型偏差仍要求跨 seed。
4. 中央驻留与外圈热点比较必须额外折价：当前 NPC 偏中央，方向会压低中央策略。最终入选版本仍须用少量平台配额确认。
5. 保存 seed、map、两份 `.so` hash、dispatch 模式和 `scenario_digest`；没有这些元数据的结果不可复现。
