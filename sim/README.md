# GoldRush 2.0 本地高保真模拟器

> 目标：把平台配额留给最终确认，用本地**同种子配对 A/B**筛选策略改动。
>
> 本模拟器把两类误差分开：机械规则由官方全信息日志逐轮精确回放验证；私有的生成分布与 NPC 策略只能拟合，绝不冒充官方真值。

## 1. 三分钟上手

### 1.1 跑一局

```bash
python3 sim/cli.py \
  --p1 /path/to/a.so \
  --p2 /path/to/b.so \
  --map map1 \
  --seed 42 \
  --games 1 \
  --dispatch fixed \
  --fixed-costs 200,201 \
  --output-dir /tmp/gr-single \
  --jobs 1
```

macOS arm64 不能加载比赛用 Linux x86-64 `.so`；可先用内置 `stay` / `scripted` 做功能测试，正式 `.so` 请在开发机运行：

```bash
python3 sim/cli.py --p1 stay --p2 scripted --map map1 \
  --seed 42 --games 1 --output-dir /tmp/gr-smoke
```

### 1.2 推荐：同种子、换座配对 A/B

```bash
python3 sim/cli.py \
  --p1 /path/to/baseline.so \
  --p2 /path/to/candidate.so \
  --map map1 \
  --seed 1000 \
  --games 20 \
  --paired \
  --dispatch fixed \
  --fixed-costs 200,201 \
  --output-dir /tmp/gr-paired \
  --jobs 8
```

每个 seed 跑两腿：A/P1 对 B/P2、B/P1 对 A/P2。两腿共享同一场景摘要 `scenario_digest`，金币/炸弹意图和 NPC 随机种子均不受策略 RNG 消耗影响。比较 `summary.json` 中两版本跨座位的净收入差，不比较单局绝对收入。

### 1.3 验证

完整验证依赖本地忽略目录中的官方日志：

```bash
python3 sim/validate.py --repo . --output /tmp/gr-validation.json
python3 sim/calibrate_generation.py \
  logs/gr_data/full/g0.txt logs/gr_data/full/g1.txt logs/gr_data/full/g2.txt \
  --output /tmp/generation.json
python3 sim/calibrate_views.py --repo . --maps sim/maps.json \
  --output /tmp/visibility_snapshot.json
```

`validate.py` 只有确定性机械/格式验收失败才返回非零；私有模型偏差进入 `fitted_warning`，不会伪装成机械失败。

## 2. CLI 契约

| 参数 | 含义 |
|---|---|
| `--p1`, `--p2` | 两个 `.so` 路径，或内置 `stay` / `scripted` |
| `--map` | 已注册地图名（含 `final_photo_1/2/3`）、地图 JSON、日志第二行 JSON，或任意完整官方日志 |
| `--seed` | 整数或字符串基种子；相同输入与非 measured 模式产生逐字节相同日志 |
| `--games` | 单局数；`--paired` 时表示配对样本数，每个样本两腿 |
| `--dispatch` | `fixed`（默认）、`p1`、`p2`、`measured` |
| `--fixed-costs` | `fixed` 模式下 P1/P2 的确定性纳秒值；相同耗时 P1 先 |
| `--output-dir` | 官方兼容 `.log` 与确定性 `summary.json` 的输出目录 |
| `--jobs` | `ProcessPoolExecutor` 并发数；每项任务使用新进程，重置 `.so` 全局状态 |

`measured` 用 `perf_counter_ns` 测量真实 ctypes 调用耗时，会影响先手且天然不可逐字节复现。需要可复现实验时不要使用它。

日志保持官方三段格式：第一行选手名、第二行 17×17 地图、随后 500 行回合 JSON。已用**未修改**的 `tools/gamelog.py` 实测解析通过。

### 快照边界（容易错一轮）

在 r=5,10,…,495 发布，标签是 `[r-5,r-1]`：

- `enter` / `leave` / `gold_collected` 聚合行动轮 r-5..r-1；
- `gold_remaining` / `occupants` 采样 **start[r]**，即本轮生成后、任何移动前；
- `gold_generated` 对应相邻 start 采样间的生成 r-4..r，首次 r=5 因从空地 bootstrap 而含 r=0..5。

这套看似错位的语义逐区 1485/1485 精确；按标签直觉统计生成量仅 17/297 个快照全对。

## 5. 生成模型标定

### 5.1 金币

- 全局 3 局/1500 轮，快照生成与剩余约束均零残差，1500/1500 地面物料守恒。
- 中央常规轮拟合：每轮格数 Poisson λ≈1.744，金额近似 `Uniform{1..10}`。首轮 50 格初始化的潜在拆分无法辨识，模型不声称复刻官方 RNG。
- 外圈共确认 121 次生成事件，间隔 8..16 轮；每次 7..13 个不同格。事件形状和值从经验直方图采样。
- 模拟器 8 seed 的热点落点占比 0.5531，真值 0.5412，差 1.2 个百分点。

### 5.2 日志行 2 的 token `2`：不是炸弹候选位

仓库旧说明把 `2` 写成“炸弹刷新位”，全信息日志直接推翻了它。炸弹会出现在全部非墙可用格，token-2 格也会被炸。

`2` 的实测语义是**外圈金币高频热点**：

- 3 局外圈落点 1142 个，其中 618 个在 20 个 token-2 格，占 54.12%；
- 20/20 热点每局都被使用；与中央 9×9 零重叠；
- 原始单格生成率约为普通外圈格 9.67 倍；当前无放回采样器用专属拟合权重 11.336。

需要修正但本任务按边界未修改的旧位置：`tools/gamelog.py` 顶部格式注释、`AGENT.md §3` 对日志第二行的描述。

### 5.3 炸弹

- r=0,20,…,480 共 75/75 波；非波相邻 start/end 炸弹集合无刷新变化；
- 每波在全部 249 个 map1 非墙格中，先排除金币、玩家、NPC，再按 Bernoulli p≈0.0789 采样；
- token-2 热点仍可生成炸弹。其原始炸弹率偏低是金币长期占位降低 eligibility，不是特殊排除规则。

## 6. 对策略有用的实测情报：外圈热点坐标

坐标为 0-based `(row,col)`。map1 的“热点”语义由 3 份全信息日志证实；map2 坐标来自相同 line-2 token，语义按同一地图格式推断，尚无 map2 全信息日志交叉验证。

**map1（20 格）**

```text
(0,4) (0,5) (0,12) (1,6) (1,10)
(5,0) (5,16) (7,1) (7,15) (9,2) (9,14)
(11,0) (11,16) (12,3) (12,13)
(15,6) (15,10) (16,4) (16,5) (16,12)
```

**map2（20 格）**

```text
(0,4) (0,8) (1,6) (1,12) (3,10)
(5,0) (5,16) (7,2) (7,14) (9,1) (9,15)
```

这解释了“外圈总池大但全职巡逻仍可能判负”：产出不是均匀铺满外圈，而是高度集中在少量格。正赛新图可直接把任意日志传给 `--map`，token `2` 会自动进入热点权重层。

## 7. NPC：最弱的一环

NPC 官方策略不公开，现有 3 局不足以精确辨识。当前模型保留每步最大化 `gold / BFS_distance^4`、按最短路移动并重规划的拟合核心；每轮 NPC 顺序由独立确定性种子生成，且**每个 NPC 在其真实 dispatch 时点**读取快方和前序 NPC 已更新的地面。

本次只加入一个有直接语料证据的类别规则：先照旧抽取贪心目标和最短路首步；若该步会进入 `-3` 炸弹，且存在合法的非炸弹 cardinal 方向，就通过注入 RNG 从稳定 action-code 顺序的候选中选择替代方向。它不是分数 penalty，没有概率、阈值或任意系数；无可达金币时的漫游逻辑不变，`stay` 也没有被偷加为避弹候选。

证据与动作覆盖：

- 全局 NPC 真值吃金：g0=5216、g1=7051、g2=6916；start occupancy 为 `[5674,1279,1123,1238,1186]`；
- 历史报告基线仍完整保留：逐动作 12192/31500、贪心并列集合 oracle 17744/31500；
- 同一份新鲜 teacher-forced 回放中，规则前后逐动作为 12207→12341，完整 action-set oracle 为 17755→18319；旧提取器与新回放的 15/11 个差异已在 `reports/npc.json` 并列披露，没有覆写旧证据；
- 已发布的 361 个“全部贪心首步均踩弹”slot 中，旧 oracle 只命中 14；347 个 miss 选择非炸弹，其中 12 个是 `stay`。cardinal-only 新规则 oracle 命中 335/361（92.80%），没有借此发明通用犹豫机制。

固定 `npc-synthetic-0/1/2` 和同一套 g0 回放弱 bot 的宏观 before/after：

| 指标 | 规则前 | 避弹后 | 真值 |
|---|---:|---:|---:|
| NPC 每局 pickup | `[9051,9272,8631]` | `[8943,8958,8543]` | `[5216,7051,6916]` |
| start occupancy R1..R5 | `[6601,1127,820,943,1009]` | `[6304,1147,923,1092,1034]` | `[5674,1279,1123,1238,1186]` |
| R1 偏移 | +927 | +630 | 0 |
| clean lifetime count / mean | 3445 / 4.1945 | 3336 / 4.8522 | 3293 / 6.2773 |
| clean lifetime median / P90 | 3 / 8 | 3 / 10 | 3 / 13 |

方向全面改善，但验收仍未达到：按三局逐一对照，NPC 仍超吃约 +24%..+71%，R1 占据仍偏高 +630，clean lifetime P90 仍短 3 轮。这个残差会**高估中央竞争、低估中央驻留，并相对高估外圈路线**；中央 vs 外圈结论必须上平台小样确认。避弹规则仍被保留，因为它由独立的 361-case 证据支持，而不是为命中宏观总量调参。

按限定顺序只评估了一个次级候选。把目标锁定在三步 NPC turn 的 target inertia，在宏观 rollout **之前**就把 oracle 从 18319 降到 16920，因此立即丢弃。NPC-ID 覆盖差异与访问状态混杂，没有导出可验证的 identity rule；旧的随机漫游/原地犹豫 sweep 已失败，本次没有重跑，也没有组合旋钮追总量。

**护栏：NPC 模型仍是本模拟器最弱的一环（新鲜逐动作仅 39.18%，oracle 58.16%）。绝对收入数值不可信；只用同种子换座 paired delta 筛方向，并以少量平台样本最终确认。上述宏观数字和语料 oracle 都是 in-sample 诊断，不是留出集证据。**

## 8. 已知偏差与未知项

1. NPC 的精确 policy、隐藏持币、身份差异和随机源未知；这是最大的、且对中央/外圈比较有方向性的误差。
2. 生成分布来自 map1 的 3 局拟合；正式赛参数可变，模型不是官方 RNG 克隆。
3. map3 只有墙，缺 token-2 外圈热点元数据；中央与炸弹可跑，外圈空间分布会失真。
4. 首轮中央 50 格初始化不能从常规生成过程唯一拆分。
5. `overlap_events` 在 g0-g2 全为空，元素语义未知；合法玩家/NPC 重叠不依赖此字段。
6. 可见敌人顺序官方不保证；模拟器给出确定性紧凑顺序，但策略不能依赖身份/顺序。
7. macOS arm64 不能执行 Linux x86-64 `.so`；机械与 Python policy 验收可本地跑，`.so` 自博弈需开发机。若源码含受保护的标量 fallback，可另编 host `.dylib` 做**行为**诊断，但它不能替代赛事机的 ISA/延迟验收。
8. **空间/驻留指标必须同策略、同口径比较。** 简化双锚 Python 基线的本地 R1 不是现役 C++，不得拿它与平台冠军的 R1 做“模拟器饱和”比较。同源策略复算：真实 10 局 R1=69.46%，模拟器 10 局=63.66%，模拟器反而低 5.8pp。差异集中在 u1，且模拟中央 remaining 更低，符合 NPC 过强导致远征段更长。

**空间 A/B 护栏：**简化 Python policy 的 paired delta 只能给该原型内部排序，绝对 R1 和平台收益不可外推；要诊断模拟器保真度，必须加载同一 C++ 源/二进制并固定 phase、cutoff、单位轮分母。NPC 残差会改变空间动力学，所有驻留类版本仍须少量平台样本终判，但不能把“不同策略的 97% vs 73%”误称为模拟器的 24pp 裂口。

## 9. 验收数字（当前主体版本）

- 机械回放：1500/1500 轮；433500/433500 end-grid cells；6000 玩家单位与 10500 NPC 轨迹/金币/pickup/actions 全精确；1500/1500 burned、trample、地面和持币物料方程。
- 快照：297 个，5 区×6 字段＝8910/8910。
- 迷雾：官方 g3-g10 共 4000 轮/8000 phase grids 零误差；当前本地 211 份日志共 105500 轮/211000 phase grids 零误差。

- ABI：`GameInput=1444B`，`GameOutput=36B`，全部字段 offset 对齐。
- 确定性：同 seed 日志逐字节一致；异 seed 分叉；配对两腿摘要相同且座位交换正确。

## 10. 给优化 Agent 的实验纪律

### 10.0 强制：本地 A/B 必须包含**后手臂**

`--dispatch fixed --fixed-costs 200,201` 让 P1 恒为快方。**一个 `--fixed-costs` 只覆盖一种行动顺序。**
我方在先手臂的收入是后手臂的约 **2.4 倍**（本地 base-vs-base 实测 2.67×/2.25×，平台观测 2.385×），
且 `engine.py:925` 的 `_dispatch` 返回 `(faster,) + 7 NPC + (slower,)` —— 快方是**单个 actor 条目**，
其两单位三步全部走完后 NPC 才动，所以**先手臂内「回合内被抢」是结构性的 0**（实测：完美预言机在
先手臂产生 0/500 轮扰动、收益恰好 +0.0）。只跑先手臂等于只测最有利、且最不可能暴露选靶缺陷的那一半。

因此：任何涉及**选靶、路由、拾取时序**的 A/B 必须同时跑 `--fixed-costs 200,201`（我方先手）与
`201,200`（我方后手），**分开汇报**，再按对手真实先手率加权。两腿共享同一 `scenario_digest`，
是干净的顺序操纵。

⚠️ **本仓库此前所有本地 A/B 结论只在「我方先手」条件下成立。** 需要复检旧判决的后手臂时，
`sim/analyze_order_sensitivity.py` 提供逐回合精确的**回合内预言机**（重建对手 `player_input` +
按真实 dispatch 时点重放 7 个 NPC；验收：预测的回合末纯地面 == 官方日志 **8000/8000** 轮，
两种顺序条件均过），可直接复用。

⚠️ 并注意**行动顺序是内生的**：我方后手轮＝我方 cost 高轮＝`ok==0` fallback 轮＝路径被挡的糟糕局面。
按行动顺序分层**不等于识别**；需要因果量时用近平局窗口（`|Δcost| ≤ 10ns`，此时谁先手近似随机）并
两个都报，两者之差即混杂大小（实测：超额顺序敏感度 2.38× 在该窗口塌到 1.13×）。


1. **只看 paired delta**：同一 seed 两腿换座，先对每个 seed 合并，再汇总中位数/均值和胜负号。
2. **不要用 measured 做收益 A/B**：默认 `fixed` 才能逐字节复现。先分别强制 P1/P2 看算法收益，再用 `measured` 单独研究先手阈值。
3. **探索至少 3 对，里程碑 6+6**：沿用 `INFRA.md §4`。平台单局收入噪声约 ±300；本地同 seed 消除了生成噪声，但 NPC 模型偏差仍要求跨 seed。
4. 中央驻留与外圈热点比较必须额外折价：当前 NPC 偏中央，方向会压低中央策略。最终入选版本仍须用少量平台配额确认。
5. 保存 seed、map、两份 `.so` hash、dispatch 模式和 `scenario_digest`；没有这些元数据的结果不可复现。
6. 空间指标报告必须写明策略身份、`start/end` phase、round cutoff、分母是 unit-round 还是 player-round；原型策略与现役策略不得横向拼成“模拟器-平台裂口”。
